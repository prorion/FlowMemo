# FlowMemo 개선 과제

작성: 2026-11-06 · 기준: Pinny Notes v1.17.0 포크 + 이번 한글화·버그 수정

## 분석 방법

- **코드 정독:** `FlowMemo.Core`와 `FlowMemo.WpfUi`의 C#/XAML 106개 파일, 약 6,600줄을 전부 읽었다.
- **원본 비교:** 원본 Pinny Notes의 `development` 브랜치에서 v1.17.0 이후 고친 내용과 CHANGELOG를 대조했다.
- **실행 검증:** 이 PC(2560×1440, 125%)에서 자동 테스트 78개가 모두 통과했다.
  - 로직 테스트 26개: FlowMemo.dll의 실제 `NoteTextBoxControl`과 도구 메뉴 명령을 실행한다.
  - UI 테스트 52개: 앱 복사본을 새 DB로 띄우고, UI 자동화와 Win32로 창 상태를 확인한다.
  - 테스트는 마우스·키보드 입력 없이 실행했다. 컴퓨터 제어는 쓰지 않았다.
- **화면 확인:** FlowMemo 창만 캡처해서 한글 화면과 배치를 눈으로 확인했다.

## 2. 아직 검증하지 못한 것 (직접 확인 필요)

자동 테스트는 마우스·키보드를 보내지 않았다. 아래 항목은 실제로 써 보며 확인해야 한다.

| 항목 | 확인 방법 | 기대 결과 |
|---|---|---|
| 한글 IME 조합 중 Enter | 빈 메모에 "안녕"까지 친 뒤, 조합 중인 상태에서 Enter | "안녕" + 줄바꿈, 글자가 깨지거나 겹치지 않음 |
| 빈 메모 첫 글자 | 새 메모에 바로 "한" 입력 | 자모가 흩어지지 않음 |
| Win+D (바탕 화면 보기) | 설정 → 메모 → 최소화 '허용 안 함' 후 Win+D | 메모가 남아 있음 |
| 세 번/네 번 클릭 | 긴 줄을 세 번 클릭 → 네 번 클릭 | 화면 한 줄 → 꺾인 줄 전체 선택 |
| 파일 끌어다 놓기 | 메모 중간에 .txt 끌어다 놓기 | 놓은 위치에 삽입, Ctrl+Z로 취소 |
| Ctrl+N, 관리 창 Delete/Enter | 단축키 입력 | 새 메모 / 삭제 확인 창 / 열기 |
| 알림 영역 메뉴 | 트레이 아이콘 우클릭 | 새 메모·메모 관리·설정·끝내기 (한국어) |
| 모니터 여러 대 (배율이 다를 때) | 메모를 다른 배율 모니터로 옮긴 뒤 재시작 | 같은 자리, 같은 크기 |

## 3. 개선 과제

### P0 · 안정성과 데이터 보호

1. **자동 테스트를 저장소에 넣기.**
   - 이번 테스트 하네스(로직 26개 + UI 52개)는 지금 저장소 밖 임시 폴더에 있다.
   - `tests/` 폴더와 `tests/run.ps1`로 옮기면, UI나 기능을 고칠 때마다 로컬에서 회귀를 잡을 수 있다.
   - GitHub Actions는 쓰지 않는다.
2. **백업과 되돌리기가 없다.**
   - 모든 메모가 SQLite 파일 하나에 들어 있다.
   - 삭제는 확인 창 하나뿐이고 휴지통이 없다.
   - 제안:
     - 시작할 때 `flowmemo.sqlite`를 날짜별로 자동 백업(최근 7개)
     - 삭제한 메모를 30일 보관하는 휴지통
     - 전체 메모를 텍스트 파일로 내보내기·가져오기
3. **불필요한 DB 쓰기.**
   - `BaseModel.SetProperty`는 어떤 속성이 바뀌어도 `IsSaved = false`로 만든다.
   - 그래서 포커스(`IsFocused`), 투명도, 색 브러시처럼 저장하지 않는 값이 바뀌어도, 창을 전환할 때마다 DB에 다시 쓴다.
   - 저장 대상 속성(내용·위치·크기·색·고정·열림)만 저장할 대상으로 표시해야 한다.
4. **메모에 시각 정보가 없다.**
   - `Notes` 테이블에 만든 시각과 고친 시각이 없다.
   - 최근 수정순 정렬, "마지막 수정" 표시, 백업 비교를 할 수 없다.
   - 스키마 v5 마이그레이션으로 `CreatedAt`, `UpdatedAt`을 추가해야 한다.
5. **`async void` 정리.**
   - `ManagementViewModel.LoadNotes`, 타이머 핸들러 등이 아직 `async void`다.
   - 전역 오류 처리는 넣었지만, 예외가 어디서 나는지 추적하기 어렵다.
   - Microsoft.Data.Sqlite의 비동기 메서드는 실제로는 동기로 동작한다. 그러니 저장소 계층을 동기 API로 단순화해도 손해가 없다.

### P1 · 한국어 사용자 경험

1. **글꼴.**
   - 기본 글꼴이 `Segoe UI`라서, 한글은 맑은 고딕으로 대체돼 영문과 높이가 어긋난다.
   - 한국어 환경에서는 기본값을 `맑은 고딕`으로 하는 것이 좋다.
   - 글꼴 크기는 16으로 고정돼 있고 설정이 없다. 크기 설정을 추가해야 한다.
2. **줄바꿈.**
   - WPF TextBox는 한국어를 어절 단위로 줄바꿈하지 못한다(CSS의 `word-break: keep-all`이 없다).
   - 그래서 메모 본문이 단어 중간에서 끊긴다.
   - 이번에 설정 창 설명 문구는 문장을 직접 나눠서 피했다.
   - 본문은 다른 편집 컨트롤(RichTextBox, AvalonEdit 등)을 검토해야 한다.
3. **맞춤법 검사.**
   - Windows 맞춤법 검사기는 한국어를 지원하지 않는다. 그래서 한국어 Windows에서는 이 기능이 사실상 꺼져 있다.
   - 영어 단어만 검사하는 옵션(en-US 검사기)이나 설정 화면 안내를 고려할 만하다.
4. **도구.**
   - 날짜/시간: 한국식 형식(`2026-11-06 (금) 오후 3:20`)을 추가한다.
   - 더미 텍스트: 한국어 문장 옵션을 추가한다.
   - 대소문자: 한글에는 의미가 없으니 영문만 있을 때 보이게 한다.
5. **영어 UI 추가.**
   - 공개 저장소라 한국어가 아닌 사용자도 쓸 수 있다.
   - `Resources/Strings.en.resx` 하나만 추가하면 영어 Windows에서 자동으로 영어가 나온다. 키는 이미 모두 분리돼 있다.

### P2 · 기능 (원본 TODO.md와 핸드오프 문서 기준)

1. **Windows 시작 시 자동 실행.**
   - 원본 `development` 브랜치(`dd31955`)에 이미 구현돼 있다.
   - 네임스페이스가 바뀌어 cherry-pick하면 충돌하므로, 코드를 보고 직접 옮겨 넣어야 한다.
2. **알림(리마인더).** 원본 `development`의 Reminders(`38c36bf`, `27cfabd`)에 있다. 일정 시각에 메모를 앞으로 가져오고, 다시 알림을 지원한다.
3. **관리 창 기능.**
   - 검색(정규식), 정렬(최근 수정·색), 메모 그룹, 카드 크기 조절을 추가한다.
   - 지금은 125px 카드로 고정돼 있고, 메모가 많아지면 찾기 어렵다.
4. **체크리스트.**
   - 서식은 원본 이슈 #28에서 미지원이다.
   - 일반 텍스트에서도 `[ ]`/`[x]` 줄을 Ctrl+Enter로 토글하는 정도는 TextBox로 구현할 수 있다.
5. **전역 단축키.**
   - 다른 앱을 쓰는 중에도 Win+Shift+N 같은 키로 새 메모를 열 수 있게 한다(RegisterHotKey).
   - 알림 영역 아이콘을 왼쪽 클릭했을 때의 동작도 설정할 수 있게 한다.
6. **동기화.**
   - DB 위치를 OneDrive 같은 폴더로 지정하는 옵션을 고려할 수 있다.
   - 이 경우 두 PC에서 동시에 실행하는 경우를 막아야 한다.
7. **시작할 때 포커스.**
   - 열려 있던 메모를 복원하면 창마다 `Show()`로 활성화되면서 포커스를 가져간다.
   - 복원하는 메모는 `ShowActivated = false`로 여는 것이 좋다.

### P3 · 구조와 코드 품질

1. **MVVM 일관성.**
   - 뷰모델이 `MessageBox`를 직접 띄우고(관리 창 삭제 확인), 로직이 코드 비하인드에 흩어져 있다.
   - 대화 상자 서비스를 만들면 테스트하기도 쉬워진다.
2. **메신저 구독 수명.**
   - 이번에 창을 닫을 때 직접 해제하도록 고쳤지만, 새 화면을 만들 때마다 잊기 쉽다.
   - 약한 참조 메신저나 `IDisposable` 구독 토큰을 도입하면 안전하다.
3. **서비스 로케이터.** `BaseTool`이 `App.Services`에서 설정을 꺼내 쓴다. 생성자로 주입받게 바꿔야 단위 테스트를 할 수 있다.
4. **설정 스키마.**
   - `Settings` 테이블이 열 60개짜리 한 행이고, 열을 추가할 때마다 마이그레이션을 손으로 쓴다.
   - 키/값 테이블이나 JSON 한 칸으로 바꾸면 설정을 추가하기 쉬워진다.
5. **설치·배포.**
   - `.vdproj`는 Visual Studio 확장이 있어야 빌드된다. 원본 TODO에도 "Find better installer"가 있다.
   - `dotnet publish -p:PublishSingleFile=true`로 포터블 zip을 만들고, 필요하면 Inno Setup이나 WiX를 쓴다. 모두 로컬 스크립트로 처리한다.
6. **버전 체계.**
   - 아직 원본 버전(1.17.0)을 쓰고 있다.
   - 업데이트 확인은 `prorion/FlowMemo` 릴리스를 보므로, 첫 릴리스 전에 FlowMemo 자체 버전(예: 0.1.0)과 태그 규칙(`v0.1.0`)을 정해야 한다.
7. **브랜딩.** 아이콘(`Images/icon.ico`, `assets/`)과 스크린샷이 원본 그대로다.
8. **접근성.**
   - 설정 창 항목은 TextBlock과 컨트롤이 형제 관계일 뿐 연결돼 있지 않다.
   - 그래서 화면 읽기 프로그램이 콤보 상자나 체크 상자의 이름을 읽지 못한다(`AutomationProperties.LabeledBy`가 필요하다).
   - 이번에는 아이콘 버튼 이름만 넣었다.
9. **투명도 기본값.**
   - 기본값이 '고정한 메모만'이지만, `AllowsTransparency`는 투명도가 켜져 있으면 모든 메모 창에 적용된다(레이어드 윈도우).
   - 레이어드 윈도우는 렌더링 비용이 크다. IME 후보 창 위치 같은 문제를 일으킬 수 있는지도 확인이 필요하다.
   - 투명도를 실제로 쓰는 메모에만 적용하는 방법을 검토한다.
10. **다크 모드 실시간 반영.** 색 모드 'Windows 설정 따르기'는 시작할 때 한 번만 읽는다. `SystemEvents.UserPreferenceChanged`를 받아 바로 바꿔야 한다.
11. **원본 추적.**
    - `upstream` 원격으로 원본 변경은 계속 받아 볼 수 있다.
    - 네임스페이스가 달라져 그대로 병합하면 충돌이 많다.
    - 원본 `development`에서 가져올 만한 것: 자동 시작, 리마인더, 제목 표시줄 버튼 사용자화(`172d817`, `331fa7b`, `9cc0bdf`).
