# FlowMemo 개선 과제

작성: 2026-11-06 · 기준: Pinny Notes v1.17.0 포크 + 이번 한글화·버그 수정
갱신: 2026-11-07 · 기반 작업(테스트 저장소 이전, 스키마 v5, 휴지통, 자동 백업, 잠금 저장, 저장 대상 정리) 반영 — 3장 P0 참고

## 분석 방법

- **코드 정독:** `FlowMemo.Core`와 `FlowMemo.WpfUi`의 C#/XAML 106개 파일, 약 6,600줄을 전부 읽었다.
- **원본 비교:** 원본 Pinny Notes의 `development` 브랜치에서 v1.17.0 이후 고친 내용과 CHANGELOG를 대조했다.
- **자동 테스트:** 이 PC(2560×1440, 125%)에서 모두 통과했다. 처음에는 79개였고, 지금은 267개다 (`tests\run.ps1`).
  - 동기화 테스트 55개: 로컬 Worker에 가상 PC 여러 대와 실제 앱을 연결한다.
  - 로직 테스트 54개: FlowMemo.dll의 실제 `NoteTextBoxControl`과 도구 메뉴 명령을 실행한다.
  - 데이터 테스트 71개: 임시 DB로 생성·v4→v5 마이그레이션·설정·휴지통·백업을 확인한다.
  - UI 테스트 87개: 앱 복사본을 새 DB로 띄우고, UI 자동화와 Win32로 창 상태를 확인한다.
- **실사용 테스트 (컴퓨터 제어):** 마우스·키보드로 직접 써 봤다.
  - 한글 IME는 실제 키보드처럼 한/영 키와 가상 키 코드로 입력했다. 컴퓨터 제어의 문자 입력은 IME를 거치지 않는다.
  - 이 테스트로 자동 테스트가 못 잡은 버그 3개를 찾아 고쳤다.
    - 빈 메모 한글 입력이 깨짐
    - 125%에서 새 메모가 기존 메모 뒤에 숨음
    - 메모가 여러 개일 때 색 견본이 사라짐
  - UX 문제 5개도 고쳤다.
    - 도구 메뉴 순서
    - 현재 색 표시
    - 고정 상태 표시
    - 잠금 표시
    - 크기 조절 테두리
- **화면 확인:** FlowMemo 창만 캡처해서 한글 화면과 배치를 눈으로 확인했다.

### 실사용 테스트에서 확인한 것

| 항목 | 결과 |
|---|---|
| 한글 IME | ✅ 확인 |
| 단축키·메뉴 | ✅ 확인 |
| 관리 창·설정 창 | ✅ 확인 |
| 창 조작 | ✅ 확인 |

- **한글 IME:**
  - 빈 메모의 첫 글자와 연속 입력("한글 한국어 입력")이 정상이다.
  - 조합 중에 Enter를 누르면 글자가 깨지거나 겹치지 않는다.
  - 한글 줄의 자동 들여쓰기도 동작한다.
- **단축키·메뉴:**
  - Ctrl+N, 세 번 클릭 줄 선택이 동작한다.
  - 우클릭 메뉴 → 도구 → 목록 → 번호 매기기가 동작한다.
  - ⋯ 메뉴로 색을 바꿀 수 있고, 텍스트 파일 저장 창에 한국어 형식과 첫 줄 파일 이름이 나온다.
- **관리 창·설정 창:**
  - 관리 창 Delete를 누르면 확인 창이 뜨고, 기본 선택은 '아니요'다.
  - 설정 창 콤보 상자가 동작하고, Esc로 닫힌다.
- **창 조작:** 끌어서 옮기기, 크기 조절, 잠금이 동작한다.

## 3. 개선 과제

### P0 · 안정성과 데이터 보호

1. **자동 테스트를 저장소에 넣기. (완료)**
   - `tests/FlowMemo.Tests`와 `tests/run.ps1`로 옮겼다. 로직 54 + 데이터 71 + 동기화 55 + UI 87 = 267개.
   - Debug 빌드로 돌려서 평소 쓰는 Release 인스턴스와 단일 실행 이름이 겹치지 않는다.
   - 화면이 잠겨 있으면 일반 창 캡처가 흰색으로 나와서, 창을 프로세스 안에서 그리는 `render` 모드를 따로 뒀다.
   - GitHub Actions는 쓰지 않는다.
2. **백업과 되돌리기. (완료, 내보내기는 남음)**
   - 시작할 때(켜 둔 동안에도 한 시간마다 확인) `backups\flowmemo-yyyyMMdd.sqlite`를 만들고 최근 7개를 남긴다. SQLite 온라인 백업 API를 쓴다.
   - 스키마를 올리기 직전에도 백업한다(`flowmemo-before-v4-….sqlite`, 최근 3개). 백업을 못 만들면 마이그레이션도 하지 않는다.
   - 관리 창 삭제는 휴지통으로 옮기고 30일 보관한다. 복원·영구 삭제·비우기가 있고, 30일이 지나면 시작할 때 지운다.
   - 남은 일: 전체 메모를 텍스트 파일로 내보내기·가져오기, 설정 창에서 백업 목록을 보고 되돌리기.
3. **불필요한 DB 쓰기. (완료)**
   - `NoteModel.PersistedProperties`에 든 속성(내용·위치·크기·색·고정·열림·잠금·시각)이 바뀔 때만 저장 대상으로 표시한다.
   - 데이터 테스트가 `NoteDto`의 필드가 모두 이 목록에 있는지 확인한다 (새 필드를 넣고 빠뜨리면 실패).
4. **메모 시각 정보. (완료, 표시는 남음)**
   - 스키마 v5에 `CreatedAt`, `UpdatedAt`(내용을 고친 시각), `DeletedAt`(휴지통), `IsLocked`를 추가했다. 시각은 UTC ISO 8601 문자열이다.
   - v5 이전 메모의 시각은 알 수 없어서 null이다.
   - 남은 일: 관리 창의 최근 수정순 정렬과 "마지막 수정" 표시.
5. **설정 저장 구조. (완료, 원래 P3 4번)**
   - 열 62개짜리 `Settings` 한 행을 키/값 테이블 `AppSettings`로 바꿨다. 키는 "구역.속성이름"이고, 설정 모델에 속성을 추가하면 저장·불러오기에 따로 손댈 필요가 없다.
   - 기본값은 DB 열의 DEFAULT에서 모델 초기값으로 옮겼다. 데이터 테스트가 v4 기본값과 새 기본값 62개가 모두 같은지 확인한다.
   - 주의: 설정 모델의 속성 이름이 곧 DB 키라서, 이름을 바꾸면 저장된 값을 잃는다.
6. **`async void` 정리.**
   - `ManagementViewModel.LoadNotes`, 타이머 핸들러 등이 아직 `async void`다.
   - 전역 오류 처리는 넣었지만, 예외가 어디서 나는지 추적하기 어렵다.
   - Microsoft.Data.Sqlite의 비동기 메서드는 실제로는 동기로 동작한다. 그러니 저장소 계층을 동기 API로 단순화해도 손해가 없다.

### P1 · 한국어 사용자 경험

1. **글꼴.**
   - 기본 글꼴이 `Segoe UI`라서, 한글은 맑은 고딕으로 대체돼 영문과 높이가 어긋난다.
   - 한국어 환경에서는 기본값을 `맑은 고딕`으로 하는 것이 좋다.
   - 글꼴 크기는 16으로 고정돼 있고 설정이 없다. 크기 설정을 추가해야 한다.
2. **줄바꿈.**
   - WPF TextBox는 한국어를 어절 단위로 줄바꿈하지 못한다(CSS의 `word-break: keep-all`이 없다).
   - 그래서 메모 본문이 단어 중간에서 끊긴다. 실사용 테스트에서 "안녕하세/요"처럼 끊기는 것을 확인했다.
   - 이번에 설정 창 설명 문구는 문장을 직접 나눠서 피했다.
   - 본문은 다른 편집 컨트롤(RichTextBox, AvalonEdit 등)을 검토해야 한다.
3. **맞춤법 검사.**
   - Windows 맞춤법 검사기는 한국어를 지원하지 않는다. 그래서 한국어 Windows에서는 이 기능이 사실상 꺼져 있다.
   - 영어 단어만 검사하는 옵션(en-US 검사기)이나 설정 화면 안내를 고려할 만하다.
4. **도구.**
   - 날짜/시간: 한국식 형식(`2026-11-06 (금) 오후 3:20`)을 추가한다.
   - 더미 텍스트: 한국어 문장 옵션을 추가한다.
   - 대소문자: 한글에는 의미가 없으니 영문만 있을 때 보이게 한다.
5. **영어 UI 추가.**
   - 공개 저장소라 한국어가 아닌 사용자도 쓸 수 있다.
   - `Resources/Strings.en.resx` 하나만 추가하면 영어 Windows에서 자동으로 영어가 나온다. 키는 이미 모두 분리돼 있다.
6. **실사용 테스트에서 나온 나머지 UX 과제.**
   - **잠금 상태 저장. (완료)** 스키마 v5의 `IsLocked`. 다시 실행해도 유지되는 것을 UI 테스트로 확인한다.
   - **고정 메모 투명도.**
     - 기본값('고정한 메모만', 80%) 때문에 고정한 메모가 포커스를 잃으면 비쳐 보인다.
     - 다른 창 위에서는 글자가 흐려진다.
     - 처음 쓰는 사람에게는 기본값을 '사용 안 함'으로 하는 편이 덜 혼란스럽다.
   - **새 메모가 고정 메모에 가려진다.**
     - 관리 창에서 만든 새 메모는 비켜서 열리지만, 고정 메모는 '항상 위'라서 새 메모의 일부를 덮는다.
     - 새 메모는 고정 메모가 없는 자리에 여는 것이 좋다.
   - **제목 표시줄 더블클릭.**
     - 더블클릭하면 메모가 화면 전체로 최대화된다.
     - 포스트잇에는 낯선 동작이라, 실수로 눌렀을 때 당황할 수 있다.
     - '기본 크기로'나 '접기(제목만 남기기)'로 바꾸는 것을 검토한다.
   - **복원할 때 창이 겹친다.** 예전 버그로 같은 자리에 저장된 메모들은 복원할 때도 겹친다. 시작할 때 정확히 겹친 메모를 비켜 놓는 정리를 한 번 하면 좋다.

### P2 · 기능 (원본 TODO.md와 핸드오프 문서 기준)

1. **Windows 시작 시 자동 실행. (완료)**
   - 사용자 레지스트리의 Run 키를 쓴다. 켜져 있는지는 레지스트리가 기준이다.
2. **알림(리마인더).** 원본 `development`의 Reminders(`38c36bf`, `27cfabd`)에 있다. 일정 시각에 메모를 앞으로 가져오고, 다시 알림을 지원한다.
3. **관리 창 기능.**
   - 검색(정규식), 정렬(최근 수정·색), 메모 그룹, 카드 크기 조절을 추가한다.
   - 지금은 125px 카드로 고정돼 있고, 메모가 많아지면 찾기 어렵다.
4. **체크리스트.**
   - 서식은 원본 이슈 #28에서 미지원이다.
   - 일반 텍스트에서도 `[ ]`/`[x]` 줄을 Ctrl+Enter로 토글하는 정도는 TextBox로 구현할 수 있다.
5. **전역 단축키. (모든 메모 보기/숨기기는 완료)**
   - 남은 일: 다른 앱을 쓰는 중에도 Win+Shift+N 같은 키로 새 메모를 열 수 있게 한다 (`GlobalHotkeyService`에 추가).
   - 알림 영역 아이콘을 왼쪽 클릭했을 때의 동작도 설정할 수 있게 한다.
6. **동기화. (완료)**
   - Cloudflare Workers + D1. 설치와 사용법은 README의 '여러 PC에서 쓰기'를 본다.
   - 남은 일: 고정·잠금 상태 동기화 여부 검토, 키 교체(분실 PC가 키를 이미 가진 경우).
7. **시작할 때 포커스.**
   - 열려 있던 메모를 복원하면 창마다 `Show()`로 활성화되면서 포커스를 가져간다.
   - 복원하는 메모는 `ShowActivated = false`로 여는 것이 좋다.

### P3 · 구조와 코드 품질

1. **MVVM 일관성.**
   - 뷰모델이 `MessageBox`를 직접 띄우고(관리 창 삭제 확인), 로직이 코드 비하인드에 흩어져 있다.
   - 대화 상자 서비스를 만들면 테스트하기도 쉬워진다.
2. **메신저 구독 수명.**
   - 이번에 창을 닫을 때 직접 해제하도록 고쳤지만, 새 화면을 만들 때마다 잊기 쉽다.
   - 약한 참조 메신저나 `IDisposable` 구독 토큰을 도입하면 안전하다.
3. **서비스 로케이터.** `BaseTool`이 `App.Services`에서 설정을 꺼내 쓴다. 생성자로 주입받게 바꿔야 단위 테스트를 할 수 있다.
4. **설정 스키마. (완료 — P0 5번으로 옮김)**
5. **설치·배포.**
   - `.vdproj`는 Visual Studio 확장이 있어야 빌드된다. 원본 TODO에도 "Find better installer"가 있다.
   - `dotnet publish -p:PublishSingleFile=true`로 포터블 zip을 만들고, 필요하면 Inno Setup이나 WiX를 쓴다. 모두 로컬 스크립트로 처리한다.
6. **버전 체계. (정함)**
   - SemVer로 **2.0.0**부터 시작한다 (원본 1.x보다 높게).
   - 버전은 `Directory.Build.props` 한 곳에서 관리하고, MSI의 `ProductVersion`도 같이 바꾼다.
   - 남은 일: 첫 GitHub 릴리스를 `v2.0.0` 태그로 만들어야 업데이트 확인이 동작한다(태그만으로는 안 되고 Release가 있어야 한다).
   - 로컬에 있는 원본 태그(`v1.x`)는 푸시하지 않는다.
7. **브랜딩.** 아이콘(`Images/icon.ico`, `assets/`)과 스크린샷이 원본 그대로다.
8. **접근성.**
   - 설정 창 항목은 TextBlock과 컨트롤이 형제 관계일 뿐 연결돼 있지 않다.
   - 그래서 화면 읽기 프로그램이 콤보 상자나 체크 상자의 이름을 읽지 못한다(`AutomationProperties.LabeledBy`가 필요하다).
   - 이번에는 아이콘 버튼 이름만 넣었다.
9. **투명도 기본값.**
   - 기본값이 '고정한 메모만'이지만, `AllowsTransparency`는 투명도가 켜져 있으면 모든 메모 창에 적용된다(레이어드 윈도우).
   - 레이어드 윈도우는 렌더링 비용이 크다. IME 후보 창 위치 같은 문제를 일으킬 수 있는지도 확인이 필요하다.
   - 투명도를 실제로 쓰는 메모에만 적용하는 방법을 검토한다.
10. **다크 모드 실시간 반영.** 색 모드 'Windows 설정 따르기'는 시작할 때 한 번만 읽는다. `SystemEvents.UserPreferenceChanged`를 받아 바로 바꿔야 한다.
11. **원본 추적.**
    - `upstream` 원격으로 원본 변경은 계속 받아 볼 수 있다.
    - 네임스페이스가 달라져 그대로 병합하면 충돌이 많다.
    - 원본 `development`에서 가져올 만한 것: 자동 시작, 리마인더, 제목 표시줄 버튼 사용자화(`172d817`, `331fa7b`, `9cc0bdf`).
